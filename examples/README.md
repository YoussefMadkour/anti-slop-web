# Examples

Three filled-in `DESIGN.md` files for fictional products. They show how the same kit reasons
differently depending on product, audience, and archetype.

They are illustrations of reasoning, not presets. Do not copy their colors, fonts, dials, or
signature elements into a real project. Copying them would create a new house style, which is
the problem this kit exists to avoid. Derive every value from your own product.

| File | Product (fictional) | Archetype | VARIANCE / MOTION / DENSITY / CHARACTER |
|---|---|---|---|
| [`saas-marketing.DESIGN.md`](saas-marketing.DESIGN.md) | Ledgerline, month-end close software, marketing site | MARKETING | 6 / 4 / 3 / 7 |
| [`industrial-ops-dashboard.DESIGN.md`](industrial-ops-dashboard.DESIGN.md) | Line Monitor, bottling plant live status | OPERATIONS + DASHBOARD | 3 / 1 / 9 / 5 |
| [`developer-tool.DESIGN.md`](developer-tool.DESIGN.md) | Tracewell, request tracing console and site | DEVELOPER_TOOL + APPLICATION | 4 / 2 / 7 / 6 |

Things to notice:
- The marketing site keeps the conventional section order and passes UI-02 without a waiver,
  because the order matches real buyer questions; it bans testimonials until real ones exist.
- The operations dashboard treats six identical columns as a usability feature and bans motion.
- The developer tool keeps dark mode and monospace, which are legitimate in its archetype, and
  makes its real trace output the signature instead of a fake terminal.
